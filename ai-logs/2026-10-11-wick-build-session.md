## 第 2 轮　AI 的方案（原文保留）

**作品：wick — 为只剩 1% 的世界而造的通信工具**

核心主张：灾难/断电/远郊/旧设备时，网络与电量最先死掉——wick 让最后 1% 电力做最多的事。

三个可演示、可量化的支柱（对应赛题三个提示词）：

1. **极限优化**：自研超紧凑编解码（字典词元 + varint 二进制打包 + 差分），一条消息从常规聊天 App 的 200–1000 字节压到十几到几十字节；每条消息实时显示字节数与能量成本。
2. **离线与弱网**：Service Worker 预缓存整套外壳，IndexedDB 本地存储，离线撰写 → 队列 → store-and-forward → 重连自动同步，可现场拔网演示。
3. **资源模拟**：电量预算引擎——选择剩余电量（1%）与网络制式，算出还能发多少条、撑多久；配「1% 模式」产品策略开关。

**关键设计决策（AI 提出，人确认）**：*这个页面本身也耗能。* 全站有一条随滚动从 100% 排到 1% 的能量轨；顶栏常驻遥测；并且有一个真正可切换的 1% 模式——它把网站自己剥到核心（不加载字体、去动效、退系统字体与单色），实测帧时间下降。**媒介本身演示论点，而不只是陈述它。**

分层架构（纯 ES Module、零运行时依赖）：`core/`（纯逻辑，无 DOM）→ `ui/`（分区渲染）→ `workers/`（编解码压测与仿真）→ `sw.js`（离线外壳）。

质量自检闭环：真实字节/能耗数据 → 单元测试 → 无外链与体积预算 → 无障碍 → 逐屏截图走查 → 迭代。

## 第 4 轮　被测试抓出的 8 个错误（真实数字）

这一节是本记录最重要的部分。

### 4.1 能耗模型把合批的好处算了两遍

第一版 `run()` 同时（a）按消息摊销固定唤醒成本，并且（b）把封帧摊进字节数。结果是 LTE 上 wick 反而更差：

```
FAIL wick beats the baseline on every radio  lte: 0.32×
```

修正为：**一次传输 = 固定唤醒成本 + 每字节成本 × 该次传输的总字节**；合批只摊薄固定成本，不再重复摊薄封帧。修正后（batchSize 8）：

```
PASS wick beats the baseline on every radio
     lte 11.7× · gsm 21.1× · lora 28.9× · ble 27.3× · satellite 12.7×
```

### 4.2 对比倍数写反

`advantage` 最初写成 `naive / wick`，方向颠倒。同一组断言抓到，修正后连同代码注释一起写清方向，避免再次反转。

### 4.3 十六进制帧渲染不出任何字节

```
FAIL codec bench produced a frame  0 bytes drawn
```

原因：`Uint8Array.prototype.map` 返回 **TypedArray**，不是字符串数组；把它的结果赋给 `innerHTML` 只会得到 `0,0,0…`。改为 `Array.from(bytes).map(...)`，并在源码里留下这个陷阱的注释。

### 4.4 无线电表键名不一致

字典里写的是 `loRa`，调用处写的是 `lora`，于是除 LTE 外的制式全部抛 `unknown radio`。统一为小写。

### 4.5 离线面板在存储被阻塞时整块空白

```
FAIL offline demo initialised its outbox   store not reported
```

原因：`initOffline()` 在 `await openStore()` 之前什么都没渲染；IndexedDB 在 iframe/隐私模式下会长时间挂起。修正为：**所有不依赖存储的 DOM 先同步构建**，存储加 2.5 秒超时并降级为内存实现。

### 4.6 `[hidden]` 被 `display: grid` 覆盖

`.field { display: grid }` 的优先级高于浏览器默认的 `[hidden] { display: none }`，导致 checkin 类型下仍显示「所需资源」「紧急度」。全局声明 `[hidden] { display: none !important }`。**这个错误只有在逐屏看截图时才会发现。**

### 4.7 截图脚本停在半路

用 URL hash 滚动 + `scroll-behavior: smooth`，截图时机与平滑滚动竞争，出现半路甚至全空白的图。改为按分区与精确尺寸渲染的夹具 `tools/shots.html`。

### 4.8 `100svh` 在 iframe 中随夹具高度变化

夹具为了「贴合分区高度」在捕获过程中改变 iframe 高度，而 `.hero { min-height: 100svh }` 跟着变，首屏内容被推到画面之外。修正：**把高度固定进 URL，捕获前不再改变 frame 尺寸**。

## 第 5 轮　关键取舍（AI 提出、人确认后写入 README 第 6 节）

| 取舍 | 我们选了什么 | 代价 |
| --- | --- | --- |
| 表达自由度 vs 体积 | 词典化 + 6-bit 打包，传输时规范化文本 | 解码端看到小写、单空格文本 |
| 时延 vs 送达率 | store-and-forward 合批 | 单条消息可能延迟数十秒 |
| 精度 vs 字节 | 位置 11 米精度、相对会话原点差分 | 无法楼层级定位；原点未共享时首帧退化 |
| 功能 vs 1% 模式 | 1% 下舍弃位置、时间与自由文本 | 主动降低信息量 |
| 品牌视觉 vs 预算 | 1% 模式放弃字体、颗粒、辉光、动效 | 视觉资产在降级模式下全部让位 |
| 开发效率 vs 依赖 | 零框架、手写 DOM 更新 | 渲染层有重复样板 |

## 第 8 轮　最后一轮自查发现的问题（补记）

交付前又发现三处并修掉：

1. **体积脚本数错了文件数**，并且**把自己生成的 `budget-data.js` 也量了进去**——表格会依赖上一次的结果。改为排除生成物，文件名与数量由脚本自动计数。
2. **i18n 静态 import 两种语言**，等于把没人读的那一种也发给了访问者。改为按语言动态 import，并新增一项测试断言：两份语言表键集必须完全一致（当前 230 个键）。
3. **默认语言没有跟随浏览器**。现在 `zh-*` 地区的访问者直接落在中文，其余落在英文，并可用 `?lang=` 覆盖、可持久化。
